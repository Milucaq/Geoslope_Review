# GeoSlope Review 0.8.0 - preparación del release

Este documento registra la preparación y validación del candidato. El usuario autorizó commit y push el 25 de noviembre de 2026; merge y despliegue requieren autorización independiente. La rama de integración es `feature/HU-114-release-0.8.0`, basada en `origin/develop` (`4d39f1d`) e instalada en el worktree `tmp/release-candidate`. La rama original y sus cambios se conservan. Se incorporan los mensajes de HU-112 de develop y se conserva el trabajo de escenarios, IA, Three.js y persistencia de las fases anteriores.

## Contenido publicable

- Código de aplicación, Isolation Forest causal y worker opcional Chronos; pruebas con datos controlados y artefactos históricos verificados.
- Persistencia SQLite aditiva y reportes inmutables, apertura de escenarios e instrumentación sin ejecutar modelos, restauración cifrada compatible con copias históricas.
- Fuentes y lockfile Three.js, bundle compilado, licencia MIT y manifiesto que vincula fuentes con salida. Los tres archivos compilados se reprodujeron byte por byte en una instalación npm aislada; npm audit no encontró vulnerabilidades.
- John Henry: solo `mesh.npz` (2 977 080 bytes), `texture.jpg` (4 421 855 bytes) y metadatos/procedencia. Se conserva la atribución y licencia declaradas en los metadatos. Century conserva NPZ, licencia y metadatos. No se incluyen GeoTIFF; el raster Century ya rastreado se retira únicamente del índice y permanece en disco.
- Documentación y resultados públicos de los experimentos sintéticos existentes en `reports/science/`. No se generan ni inventan nuevos resultados de campo.

Se excluyen runtime, credenciales, claves, bases y sidecars, backups, GeoTIFF originales, checkpoints, entornos virtuales, node_modules, CSV locales de prueba y temporales. `scripts/audit_release.py` comprueba tamaños y patrones de secretos sin leer el contenido de rutas prohibidas. Sus informes contienen nombres, tamaños y SHA256 de archivos públicos, nunca valores de credenciales.

## Instalación desde un checkout limpio

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows: .venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
python -m pip install -e .
python scripts/verify_installation.py
python scripts/verify_integrity.py
python scripts/verify_release_assets.py
python scripts/verify_clean_start.py
python -m ruff check .
python -m pytest --cov=gsreview --cov-report=term-missing --cov-fail-under=90
```

La comprobación de arranque usa `ci_artifacts`, una clave y una base temporales, y verifica que no se hayan cargado torch/transformers/Chronos. No lee ni reutiliza el runtime privado de una instalación existente. CI ejecutará esta comprobación y la suite en Ubuntu con Python 3.13. En el equipo actual solo hay Windows; WSL no está instalado y Docker no está disponible. La ejecución real en Linux queda pendiente del push autorizado y de GitHub Actions. Una prueba local no se presenta como una ejecución Linux.

## Three.js durante el despliegue

El bundle está versionado y Render no necesita Node para servirlo. El build de Render ejecuta la verificación de activos y de los 17 artefactos después de instalar las dependencias de producción. CI instala Node 22, reconstruye el bundle con `npm ci` y `npm run build`, actualiza su manifiesto y exige que la reconstrucción no produzca diferencias respecto a Git. Las fuentes y el lockfile están fijados; no hay dependencias CDN en el HTML.

El JavaScript compilado de Three.js contiene shaders GLSL de terceros con espacios de plantilla. `.gitattributes` limita la excepción de whitespace exclusivamente a `bundle/assets/*.js` y lo marca como generado. Sus bytes no se editan a mano: se verifican mediante reconstrucción y SHA256. Las fuentes, documentos y demás archivos mantienen el chequeo de espacios; no se modifica ninguna exclusión de cobertura.

Para reconstruir deliberadamente:

```bash
cd assets/three_component
npm ci --ignore-scripts --no-fund
npm run build
npm audit
cd ../..
python scripts/verify_release_assets.py --write-bundle-manifest
```

## Seguridad y worker opcional

La auditoría estricta de `requirements.txt` no encontró vulnerabilidades conocidas. Ruff, Bandit con umbral medio/alto y pip check fueron ejecutados; los hallazgos B310 del preparador de checkpoints se corrigieron con validación HTTPS de solicitudes/redirecciones y de la revisión inmutable. El índice y la selección se comprueban antes de pedir autorización del commit.

La auditoría separada del lock del worker informó **9 entradas, correspondientes a 6 IDs PYSEC únicos**, todas en `transformers==4.57.6`: PYSEC-2025-217, PYSEC-2026-2288, PYSEC-2026-2289, PYSEC-2026-2290, PYSEC-2026-3929 y PYSEC-2026-4174. No se ocultan ni se suprimen esos avisos. Se mantienen las versiones usadas en los experimentos para no declarar compatibles versiones nuevas sin ensayos científicos. La aplicación no descarga modelos automáticamente; el worker exige checkpoint local verificado, safetensors y `trust_remote_code=False`, y se bloquea en Render. Estas defensas no equivalen a certificar que el entorno opcional carece de vulnerabilidades.

Referencias: [advisory de LightGlue](https://github.com/advisories/GHSA-fgcw-684q-jj6r), [advisory de configuración de atención](https://github.com/advisories/GHSA-29pf-2h5f-8g72). Actualizar Transformers y revalidar Chronos es una tarea separada pendiente antes de habilitar el worker en producción. La documentación de [Chronos](https://github.com/amazon-science/chronos-forecasting/releases) indica soporte para Transformers 5, pero no se ha medido aquí esa combinación ni se han sustituido sus resultados históricos.

La variante `torch==2.9.1+cpu` no fue reconocida por el proveedor PyPI de pip-audit y figura como omitida; no se presenta como auditada ni libre de avisos. Se consulta también la versión upstream sin el sufijo local para identificar avisos aplicables, sin instalar ni cambiar el binario CPU. Las herramientas de cuadernos se separaron a requirements-dev, sin cambiar los pins científicos de producción. Bandit/pip-audit/pytest-cov quedan fijados a versiones comprobadas.

La consulta upstream de `torch==2.9.1` devolvió 5 entradas: PYSEC-2026-139, PYSEC-2025-194, PYSEC-2025-195, PYSEC-2026-2286 y PYSEC-2026-1856. Las dos últimas comparten CVE-2026-24747. Es una señal para revisar la variante CPU; no es una auditoría binaria de esa variante. Los avisos se conservan en la evidencia del release. CI mantiene una compuerta estricta para las dependencias del entorno web y publica por separado la auditoría del worker experimental con advertencia visible; no se usan ignore-ID para ocultar estos resultados.

## Render: preparación no equivale a persistencia

Se mantiene plan gratuito, sin disco persistente. El entry point usa por defecto un runtime temporal y respeta un runtime proporcionado explícitamente por el administrador. No se configura ni contrata almacenamiento. Los archivos locales de Render Free son efímeros; la persistencia SQLite y las restauraciones aquí verificadas son locales y requieren conservar archivos y clave. Un backup en el mismo filesystem efímero no es respaldo externo. Véase [documentación oficial](https://render.com/docs/free).

## Validación del candidato

- Grupo focal de publicación, terreno sin GeoTIFF, login y límites de Chronos: **38 aprobadas en 35.17 s**.
- Bundle compilado de forma aislada: tres archivos idénticos; tres activos topográficos optimizados verificados. Npm audit: sin vulnerabilidades.
- Instalación nueva desde requirements-dev, sin Chronos: `pip check` aprobado. Exportación de los 332 archivos del índice, sin directorio `data` ni archivos privados; verificación de arranque desde el checkout con runtime/clave temporales y cero imports de torch/transformers/Chronos aprobada en Windows/Python 3.13.14.
- Primera suite completa del checkout limpio: **285 aprobadas y 1 fallo por timeout en 660.19 s**, cobertura **95.25 %**. La prueba nueva del visor sin GeoTIFF heredaba 3 s de AppTest; se ajustó explícitamente a los 25 s utilizados por las demás pruebas de interfaz, conservando todas sus aserciones.
- **Suite integral definitiva: 286 aprobadas en 971.77 s (16:11), salida 0; cobertura 95.25 % (3749/3936 instrucciones, 187 pendientes)**. Se conservan las 258 pruebas de entrada y se añaden 28, sin exclusiones ni reducción del umbral del 90 %. Se ejecutó `python -m pytest --cov=gsreview --cov-report=term-missing --cov-fail-under=90` en el entorno nuevo y una exportación estable del índice.
- Una advertencia `PytestCacheWarning`: Windows denegó el renombrado del directorio temporal de caché de pytest al finalizar. No hubo ResourceWarning de SQLite ni fallo funcional; no se silenció la advertencia. Evidencia local en `tmp/release-clean-tests-final.log` (fuera del índice).
- Ruff: **All checks passed**. Bandit medio/alto: **0 hallazgos**; auditoría estricta de producción: **sin vulnerabilidades conocidas**; `pip check`: sin conflictos; npm audit: **0 vulnerabilidades**. Integridad: **17 artefactos**, 7178 registros, 49 prismas, 48 episodios y 20 episodios candidatos.
- Comparación de los 332 objetos del índice con el checkout probado mediante los filtros de Git: **cero diferencias funcionales**. Solo cambia documentación posterior a las pruebas (contexto, README, manual de instalación e informe/borrador del release). `git diff --cached --check` y `git diff --check` aprobados; los 17 artefactos conservan sus SHA256 en original, candidato y exportación. El GeoTIFF permanece en ambas copias locales y no está en la exportación pública.
